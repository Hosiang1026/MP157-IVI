# 量产车机协议指南（针对 2018 款柯迪亚克）

面向本仓库 **MP157-IVI** 若要替换/旁路原厂娱乐主机、做成可上车演示或量产级对接时，按**优先级**需要掌握的协议与硬件路径。

> **车型锚定**  
> - 车型：上汽大众斯柯达 **柯迪亚克（Kodiaq）一代 NS7**，约 **2017–2019 款（含 2018）**  
> - 平台：大众集团 **MQB**  
> - 原厂娱乐：**MIB2 / MIB2 Standard-High**（国内常称 MIB 二代；配置因 Swing / Bolero / Amundsen / Columbus 及国产零件号而异）  
> - 本文零件号为**常见装配示例**，实车以 **VCDS / ODIS / OBDeleven** 读出的控制单元为准。

### 文档能做什么 / 不能做什么

| 看完本文之后 | 仍然做不到（需另备资料/硬件） |
| --- | --- |
| 知道 P0→P4 先做什么 | 直接写出可上车的完整 DBC |
| 知道接哪类 ECU、哪类线束 | 不查实车就焊死 Quadlock 针脚 |
| 知道本仓库改哪些模块 | 不插 CAN 分析仪就断言报文 ID |
| 能列采购清单与验收标准 | 合法量产认证、MFi/AA 过审 |
| 能按「阶段 0～3」开工 | 关闭组件保护/破解网关的教程（本文不提供） |

**结论**：本文是架构 + 上手流程手册；**实车诊断记录 + 线束/CAN Box + 只读抓总线 + 改代码** 四件套齐了，才能适配你的 2018 柯迪亚克。

### 0.2 总线拓扑（示意）

```
                    ┌─────────────┐
                    │  OBD-II 口  │
                    └──────┬──────┘
                           │ 诊断 CAN
                    ┌──────▼──────┐
     动力 CAN ──────┤  J533 网关  ├────── 舒适/车身 CAN
     扩展 CAN ──────┤ 3Q0 907 530*├────── 信息娱乐相关 CAN
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
         ┌────────┐  ┌──────────┐  ┌─────────┐
         │ 仪表17 │  │ 主机 5F  │  │ BCM/空调 │
         └────────┘  │ MIB2     │  └─────────┘
                     │5Q0 035*  │
                     └────┬─────┘
                          │ 高配可选 MOST150
                          ▼
                     ┌──────────┐
                     │ Dynaudio │
                     │ 功放/光纤 │
                     └──────────┘
```

2018 款 MQB **主流是 CAN +（高配）MOST**，**不是**以 SOME/IP 为主的以太网架构。SOME/IP 对本车优先级靠后（见 P3）。

### 0.3 与本项目（STM32MP157 / ivi-shell）的接车形态

| 形态 | 做法 | 适用 |
| --- | --- | --- |
| A. 并联只读 | MP157 经 **CAN 收发器** 挂信息娱乐 CAN / 舒适 CAN，**只听不发** | 先做车速/档位/油量显示 |
| B. 替换主机 | 拔原厂 MIB，Quadlock 线束 + **CAN 解码盒** → MP157；保留方向盘、雷达、空调显示 | 售后一体机常见路径 |
| C. 保留主机做投屏 | 原厂 MIB 不动，MP157 仅做副屏/研发台架 | 不碰总线，功能受限 |

量产级「打通」通常走 **B + OEM 授权信号表**，或主机厂把 MP157 做成正式 5F 替代件并过组件保护/认证。

## P0 — 不上车就没有「真车机」

### 1. CAN 总线 + J533 网关

#### 原理

- CAN：双绞线差分（CAN_H / CAN_L），多节点广播报文（ID + 数据场）。  
- MQB 上有多条 CAN（动力、舒适、扩展、诊断等），**J533 网关**做路由、过滤、休眠唤醒与诊断桥接。  
- 娱乐主机挂在允许的总线段上，**车速、里程、灯光、空调状态、方控按键**等多经网关转发后到达 5F。

#### 柯迪亚克怎么用

1. 用诊断仪读 **19-Gateway**，确认零件号与编码。  
2. 向主机厂/售后渠道要 **信息娱乐相关 DBC**（或合法逆向 + 台架验证，注意法律与安全）。  
3. 关键信号示例（名称以实车 DBC 为准）：车速、发动机转速、挡位、手刹、门锁、外温、油量、转向灯、倒车灯、方向盘按键。

#### 与 MP157 打通

```
柯迪亚克 CAN 线 ──► TJA1051/SN65HVD230 等收发器
                 ──► MCP2515 / 板载 CAN / USB-CAN
                 ──► Linux SocketCAN (can0)
                 ──► ivi-shell：替换 VehicleState 底层
```

- **只读阶段**：订阅报文 → 更新 QML 车速/档位/胎压等。  
- **可控阶段**：仅发送 DBC 中标明「主机可发」的 ID（门锁、部分舒适功能）；**禁止**发动力/底盘安全域报文。  
- 硬件选型示例：  
  - 收发器：`TJA1051T`、`SN65HVD230`  
  - 控制器：STM32 片内 FDCAN（若引脚引出）或 `MCP2515` + SPI  
  - 台架：Peak PCAN、CANable、周立功 USBCAN

#### 接线要点

- 从 **主机 Quadlock 的 CAN 脚**或网关侧娱乐 CAN 并联（需接法表，错误接线可影响整车）。  
- 共地；终端电阻 120Ω 仅在总线两端，并联节点**不要**再加终端。  
- 点火/ACC：用原车 **Kl.15 / Kl.30 / ACC** 逻辑给 MP157 上下电，避免亏电。

### 2. UDS 诊断（ISO 14229）+ 经网关路由

#### 原理

- **UDS**：统一诊断服务（读 DID、清 DTC、例程、刷写等）。  
- OBD-II 口物理层多为 CAN；MQB 上请求先到 **J533**，再路由到 5F/17/09 等。  
- 地址：逻辑地址 / 扩展地址依 ODX/ASAM 数据集（如网关 `EV_GatewNF`）。

#### 柯迪亚克怎么用

- 匹配组件保护、编码主机、读故障：用 **ODIS / VCDS / OBDeleven**。  
- 量产产线：DoIP 或 CAN 上的 UDS 刷写脚本（需 OEM 权限与签名）。

#### 与 MP157 打通

- 短期：不实现完整 UDS 服务器；保留 OBD 仍指向原网关。  
- 若 MP157 **替代 5F**：必须实现网关期望的诊断响应与编码，否则仪表报「信息娱乐故障」。此为高成本项，优先用「CAN 解码盒模拟原主机部分报文」降低难度。

---

### 3. 电源、地线、点火与物理连接器

#### 原理

车机不是常电蛮干：要区分常电（Kl.30）、点火（Kl.15）、ACC，配合网关休眠，否则静电流过大导致亏电。

#### 柯迪亚克硬件

- 主机侧主流为大众集团 **Quadlock（Fakra 组合）** 电源/扬声器/CAN/天线座。  
- 倒车摄像常见 **CVBS**（RCA 或专用针脚）；天线为 **Fakra**（收音机/GPS）。  
- 高配 **MOST** 为光纤环网插头（橙头），拔主机前需按维修手册保护端口。

#### 与 MP157 打通

| 信号 | 用途 |
| --- | --- |
| Kl.30 | 常电 / 维持 RTC、快启（慎用） |
| Kl.15 / ACC | 系统开机 |
| GND | 与车身共地 |
| ILL / 大灯信号 | 夜间背光（可经 CAN 替代） |
| 喇叭输出 | 无原车功放时接模拟功放；有 Dynaudio 见 P2 MOST |

推荐：**成品柯迪亚克专用线束 + CAN Box**（售后 Android 机同款思路）接到载板，再 USB/UART/以太网连 MP157，避免割原车线。

## P1 — 车主体验（互联 + 人机）

### 4. BAP（Bedien- und Anzeigeprotokoll，大众组）

#### 原理

- VW/Skoda 在 CAN 上封装的**操作与显示协议**，主机与仪表、空调、辅助驾驶显示等交换「功能块」状态（比原始信号更偏 UI）。  
- 原厂 MIB 大量依赖 BAP；只扒车速 CAN 不够还原空调屏、行车电脑菜单等。

#### 柯迪亚克怎么用

- 原厂：5F ↔ 17 / 空调等自动完成。  
- 换机：多数 **CAN Box** 固件内模拟部分 BAP/报文，使空调屏、胎压、辅助显示不报错。

#### 与 MP157 打通

1. 阶段 1：外置 CAN Box，MP157 只做人机，方控/空调交给盒子。  
2. 阶段 2：自研解析 BAP（需协议资料与抓总线），纳入 `VehicleState` / 空调页。

---

### 5. 蓝牙：HFP / A2DP / AVRCP / PBAP

#### 原理

| Profile | 作用 |
| --- | --- |
| HFP | 免提通话 |
| A2DP | 手机音乐到车机 |
| AVRCP | 播放/切歌控制 |
| PBAP | 通讯录同步 |

#### 柯迪亚克原厂

- 主机内置蓝牙模块；顶配 `866B/C` 等可双手机连接（视编码）。  
- 麦克风经主机线束接到顶棚/A 柱麦。

#### 与 MP157 打通

```
手机 ──BT──► 板端蓝牙模组（如 RTL8822 / AP6212 等）
         ──► BlueZ + ofono/PipeWire
         ──► CallSession / MediaSession / BluetoothMediaHub
```

- 硬件：USB 蓝牙或 SDIO WiFi/BT 模组；外接原车麦或独立麦。  
- 软件：补齐 Linux BlueZ（README 已标明板端未接）。

---

### 6. Wi‑Fi + Apple CarPlay（无线）/ iAP2

#### 原理

- 无线 CarPlay：蓝牙协商 + Wi‑Fi 传输视频/音频；底层含 **iAP2**、AirPlay 媒体通道。  
- 需 **MFi** 认证芯片/流程才能合法量产。

#### 柯迪亚克原厂

- 视主机与编码：USB CarPlay / 无线能力因 `5Q0 035 866*` 与 FEC 而异。  
- USB 口在手套箱/扶手，经主机 USB Hub。

#### 与 MP157 打通

- 本仓库已有 `src/carplay/` 与 offline-mfi 演示路径。  
- 上车：板端 **Wi‑Fi AP** + **蓝牙** + USB（有线备选）；天线外置。  
- 量产：正式 MFi，不能依赖演示用 offline 材料。

---

### 7. USB Host：Android Auto（AOAP）/ 百度 CarLife

#### 原理

- **AOAP**：手机以 Android Open Accessory 模式与主机建链，再跑 AA 协议（TLS、视频、音频）。  
- **CarLife**：百度车机互联；国产 2018 顶配 `5Q0 035 866C` 宣传点包括 CarLife。

#### 柯迪亚克原厂

- USB 数据线接主机；AA/CarLife 由原厂 MIB 完成。

#### 与 MP157 打通

- AA：扩展现有 `AndroidAutoSession`（现多为探测/演示）。  
- CarLife：需单独 SDK/协议实现（本仓库无）。  
- 硬件：USB Host 口从原车 USB 线引出到 MP157（注意供电与数据脚）。

## P2 — 影像、定位、音响完整体验

### 8. MOST150（高配 Dynaudio）

#### 原理

- **MOST**：塑料光纤环形总线，传多声道数字音频与控制。  
- 主机是环上节点；功放、部分音源设备串联。

#### 柯迪亚克怎么用

- 装配 **Dynaudio** 时，维修手册要求拆主机时处理 **MOST 插头**，损坏需换光纤段。  
- 换机需 **MOST 适配器**（售后常见型号思路如 Dynavin D8-MO150-V 一类），否则高配音响无声。

#### 与 MP157 打通

- 无 Dynaudio：主机模拟/功放输出即可。  
- 有 Dynaudio：采购 MOST↔模拟/I2S 适配器，或保留原厂功放链路，MP157 只输出适配器接受的格式。  
- **不要**擅自剪断光纤。

---

### 9. 倒车影像 + OPS 雷达

#### 原理

- 摄像头：多为 **CVBS**（或后期 LVDS）视频进主机。  
- OPS：超声波雷达距离经 **CAN** 到主机，叠加条形 UI。

#### 柯迪亚克 / 本项目

- 原厂：R 档触发影像 + OPS。  
- 本仓库：`VehicleState` 档位 R → `CameraService` 全屏；雷达条现为演示正弦。  
- 打通：CVBS→采集芯片（如 `TVP5150`）→V4L2；雷达 ID 进 SocketCAN 驱动真实条。

---

### 10. GNSS（NMEA）

#### 原理

模块输出 `$GNGGA/$GNRMC` 等 NMEA 语句；导航用地图 SDK 算路。

#### 柯迪亚克

- 原厂 GPS 天线 Fakra 接主机；国产主机带导航数据。

#### 与 MP157 打通

- `GpsSource` 已支持串口 NMEA；接 USB-GPS 或 UART 模组（如 u-blox M8/M10）。  
- 天线：有源天线 + 3.3/5V 馈电，注意车顶天线复用需合路器。

---

### 11. 音频链路与音权

#### 原理

导航播报、电话、媒体、倒车提示需 **优先级抢占与 ducking**（本仓库 `AudioFocus`）。

#### 打通

- 无功放：MP157 → 功放 IC（如 PAM8403 仅演示）→ 扬声器（阻抗匹配）。  
- 有原车功放：按 MOST/模拟输入规范接入，切勿直驱原车扬声器超功率。  
- 电话上行：AEC 回声消除（麦 + 参考信号）。

## P3 — 量产合规与新架构（2018 款次要但规划要懂）

### 12. SOME/IP / 车载以太网

#### 原理

服务发现 + 方法/事件调用，跑在 IP 上；新平台域控常用。

#### 对 2018 柯迪亚克

- **原车几乎不依赖 SOME/IP 做娱乐主路径**。  
- 学习价值：面向换代车型 / MQB Evo 以后；本车优先 CAN+BAP。

---

### 13. TLS、OTA、Secure Boot、ISO 21434

| 项 | 作用 | 与柯迪亚克/本项目 |
| --- | --- | --- |
| TLS/PKI | AA、云端、账号 | AA 完整会话需要 |
| OTA 签名 / R156 | 合法远程升级 | 现为应用包 OTA，非 A/B |
| Secure Boot | 防刷恶意系统 | MP157 需 OTP/签名链 |
| ISO 21434 | 车载网安 | 接 CAN 后必须威胁分析 |

---

### 14. ISO 26262（功能安全）

见 README「真车控相关概念」。对柯迪亚克换机项目：

- 允许：显示车速、控空调/座椅类舒适功能（在 OEM 允许范围内）。  
- 禁止：经娱乐屏直接干预刹车、转向、气囊等。  
- 方向盘按键：只做媒体/电话/语音，经原网络路径转发。

## 推荐落地顺序（绑定本车 + 本仓库）

```
1. 电源/ACC + Quadlock 线束台架通电
2. SocketCAN 只读：车速、档位、进口 R → 替换 VehicleState 模拟
3. 倒车 CVBS + 真实 R 档信号
4. CAN Box / BAP：方控、空调信息不报严重故障
5. BlueZ：HFP + A2DP（板端）
6. Wi‑Fi + CarPlay / USB AA（认证前仅工程）
7. Dynaudio → MOST 适配（若实车有）
8. 导航 SDK + GNSS
9. UDS/组件保护策略（若彻底替换 5F）
10. OTA 签名 + 网安（ISO 21434）+ 功能安全材料
```

## 实车确认清单（动手前必做）

1. 记录 VIN，用诊断仪导出 **19 / 5F / 17** 零件号与编码。  
2. 确认娱乐主机是 `5Q0 035 866*`（国产导航）还是欧规 `840*` / Columbus **MHI2**。  
3. 确认是否 **Dynaudio**（有则准备 MOST）。  
4. 确认倒车影像插头规格（CVBS 电平）。  
5. 向合法渠道索取或购买 **柯迪亚克 MQB 线束针脚定义 + CAN 信号说明**；不要假设与高尔夫/速派针脚完全相同。  
6. 评估 **组件保护**：换机后仪表与主机需匹配，否则功能受限或常亮故障灯。

### 15.1 诊断仪操作要点（OBDeleven / VCDS / ODIS）

1. 点火 ON（发动机可不起步），连接 OBD。

## 17. CAN 只读摸底流程（无官方 DBC 时）

目标：自己建立「信号笔记本」，**禁止**一上来乱发报文。

### 17.1 接法

1. 形态 A：在主机侧娱乐/舒适 CAN 上 **并联** CAN_H/CAN_L（先确认线色与针脚，见下节）。  
2. 分析仪波特率 MQB 常见 **500 kbit/s**（以实车为准；不对就试不出稳定帧）。  
3. 软件：`candump`、SavvyCAN、PCAN-View 等，录制 `.asc` / `.blf`。

### 17.2 对照实验（停车、拉手刹）

| 动作 | 观察 |
| --- | --- |
| 点火 ON/OFF | 哪些 ID 出现/消失 |
| 踩刹车 | 哪字节变化 |
| 挂 R / D / N / P（AT） | 找档位候选 |
| 转向灯左右 | 找灯光候选 |
| 按方向盘音量± / 接听 | 找方控候选 |
| 车速：仅平坦路、副驾操作记录仪时由驾驶员低速短距验证 | 找车速候选（注意安全） |

### 17.3 记录模板

| CAN ID (hex) | 周期 ms | 字节/位 | 物理量 | 换算公式 | 验证次数 |
| --- | --- | --- | --- | --- | --- |
| | | | 车速 km/h | | |
| | | | 档位 | | |
| | | | 倒车灯/R | | |

把稳定结果写进自建 `kodiaq2018.dbc`（或 JSON），再写解析代码。**网上流传的高尔夫/速腾 ID 不可直接当柯迪亚克真理。**

### 17.4 安全规则

- 阶段 1：**只听不发**。  
- 阶段 2：仅在台架或停车、且信号已在只读阶段验证后，试发「舒适域」报文。  
- 任何导致仪表报警、转向沉重、制动异常的试验立即停止。

## 18. Quadlock / 线束说明（原则，非万能针脚表）

大众集团主机常用 **Quadlock** 组合插头（电源+扬声器+CAN+天线 Fakra 等）。  
**不同年款/音响/导航配置针脚可能不同**，本文不给出可直接焊接的完整针脚表，避免照表接错烧毁设备。

### 18.1 正确做法

1. 购买标注 **Skoda Kodiaq 2017–2020 / NS7** 的 plug & play 线束。  
2. 向卖家索取 **针脚定义 PDF**，与实车插头拍照核对。  
3. 至少用万用表确认：  
   - 常电（约 12V 永电）  
   - ACC/点火（钥匙 ON 才有电）  
   - GND  
   - CAN_H / CAN_L（差分、静态约 2.5V 附近，以实测为准）  
4. 倒车视频线：确认是 CVBS 及地线，不要接到 CAN。  
5. 天线：收音机/GPS 的 Fakra 颜色与键位不要混插。

### 18.2 与 MP157 的电气隔离

```
车电 12V ──► 车规 DCDC（如 12V→5V/3.3V）──► MP157
车 CAN  ──► 收发器（隔离型更佳）──► SocketCAN
车 GND  ──► 与 DCDC/逻辑地单点连接，避免接地环
```

禁止把车载 12V 直接接到 MP157 模块电源脚。

## 19. 本仓库分阶段改代码清单

当前 `VehicleState` 为定时器模拟（`speed` / `gear` / `parkRl`…）。对接实车时建议**保持 QML 属性不变**，只换数据源。

### 阶段 0 — 台架通电（不改协议）

- [ ] 线束 + CAN Box + 显示屏点亮 `ivi-shell`  
- [ ] ACC 掉电后进程可干净退出（配合 systemd）  
- [ ] 日志写入不撑满 eMMC（已有轮转则验证）

### 阶段 1 — CAN 只读 → VehicleState

新建例如 `src/core/CanVehicleSource.cpp`（名称自定）：

- [ ] `socketcan` 打开 `can0`（或 USB-CAN 映射名）  
- [ ] 按自建 DBC/JSON 解析车速、档位、手刹、门锁、外温、油量等  
- [ ] 调用现有 `VehicleState::setGear` / 内部 setter 或增加 `applyTelemetry(...)`  
- [ ] 设置项增加「模拟 / CAN」开关（类似 `GpsSource` demo/串口）  
- [ ] 验收：`apps/vehicle` 车速与仪表目视一致；挂 **R** 触发倒车全屏

优先映射属性：

| VehicleState 属性 | 信号来源 |
| --- | --- |
| `speed` | CAN 车速 |
| `gear` | CAN 档位（R 必须准） |
| `handbrakeOn` | CAN 手刹 |
| `locked` / `doorAjar` / `trunkOpen` | CAN 车身 |
| `outsideTemp` | CAN 或继续天气 |
| `fuel` / `rangeKm` / `odometer` | CAN |
| `parkRl/Rcl/Rcr/Rr` | OPS CAN（有则接，无则保持演示） |
| `tire*` | 直接式胎压 CAN 或仪表 BAP（难，可后置） |

### 阶段 2 — 方控与音权

- [ ] CAN/CAN Box 上报方控事件 → 已有 Shell 媒体键函数  
- [ ] 电话键 → `CallSession` / CarPlay hardkey  
- [ ] 倒车时降低媒体音量（`AudioFocus` ducking）

### 阶段 3 — 互联与影像

- [ ] 板端 BlueZ：`BluetoothMediaHub` / HFP  
- [ ] CarPlay Wi‑Fi AP；AA USB Host  
- [ ] CVBS → V4L2 → `CameraService`  
- [ ] GNSS → `GpsSource` → 地图/天气

### 阶段 4 — 换机完整性（成本高）

- [ ] CAN Box 消除关键故障码（空调屏、EPS 提示等）  
- [ ] Dynaudio → MOST  
- [ ] 组件保护策略与诊断响应（若宣称完整替代 5F）

## 21. 常见坑

| 现象 | 可能原因 | 处理方向 |
| --- | --- | --- |
| 无 CAN 数据 | 波特率错、接错总线、未接 ACC | 先 candump 看有没有任何帧 |
| 换机后方向盘失灵 | 未接 CAN Box 或编码不对 | 查盒子车型固件 |
| 倒车黑屏 | 视频线未接 / 制式不对 / 未识别 R | 示波器看 CVBS；确认档位信号 |
| 高配无声 | Dynaudio 未过 MOST | 加 MOST 适配，勿剪光纤 |
| 仪表组件保护 | 主机与仪表未配对 | 走正规匹配；勿用不明破解 |
| MP157 反复重启 | 供电跌落、ACC 抖动 | 加电容/稳压；软件做 ACC 去抖 |
| 亏电 | 未睡死、Wi‑Fi 常开 | 跟网关休眠策略；禁 Kl.30 狂吃电 |
| 用了别人的 DBC 车速翻倍 | 缩放因子/单位错 | 用仪表对比重标定 |
