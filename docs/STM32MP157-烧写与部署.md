# STM32MP157 烧写与部署（MP157-IVI）

从零开始：先把 **Linux 烧进开发板**，再在 PC 上 **交叉编译 `ivi-shell`**，最后 **拷贝到板子运行**。  
本仓库 **不包含** 整板 Flash 镜像，也 **不能** 用 `cmake --build` 直接代替 ST 官方烧录流程。

---

## 你要准备什么

| 类别 | 内容 |
| --- | --- |
| 硬件 | STM32MP157 开发板（如百问网 / ST DK）、7 寸 RGB 屏、电源、USB 线 |
| 存储 | microSD（从 SD 启动时）或板载 eMMC（按板子说明） |
| PC | Windows 或 Linux，用于烧录镜像、交叉编译 |
| 软件 | STM32CubeProgrammer（或板厂提供的写卡工具）、OpenSTLinux 或板厂 **Linux 镜像** |
| 交叉编译 | 与 rootfs **ABI 一致** 的 SDK（OpenSTLinux SDK / Yocto SDK）+ **Qt 6.8**（Quick、QuickControls2、Network、Gui、OpenGL、Qml） |
| 源码 | 本仓库 `MP157-IVI` |

**区分两件事**

| 步骤 | 产物 | 作用 |
| --- | --- | --- |
| **烧写系统** | `.tsv` + 分区镜像 / 整盘 `.img` | 板子能进 Linux、驱动、网络 |
| **部署应用** | `ivi-shell` + `apps/` + Qt 库 | 跑本项目的 IVI 界面 |

## 第一步：获取并烧写 Linux 镜像

### 1.1 镜像从哪来

任选其一（以你手头 **开发板配套资料** 为准）：

- **ST OpenSTLinux**（STM32MP157 官方发行版）：[STM32MP1 OpenSTLinux](https://wiki.st.com/stm32mpu/wiki/STM32MP1_OpenSTLinux_release_note)
- **百问网 / 第三方**：教程里的 **SD 卡镜像** 或 **STM32CubeProgrammer 烧录包**

镜像里需具备：内核、rootfs、显示相关驱动（DRM/KMS 或 FB）、网络（以太网或 Wi‑Fi 驱动）。**是否带 Qt6 因镜像而异**；若无 Qt6，需在 SDK/Yocto 里自行交叉编译 Qt（工作量大，建议选带 Qt 或 Yocto 自建层）。

### 1.2 用 STM32CubeProgrammer 烧录（USB / UART 常见流程）

1. 安装 [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)。
2. 开发板进入 **USB 烧录模式**（短接 BOOT 引脚或按文档进 Serial/USB DFU）。
3. 打开 CubeProgrammer → 选择连接方式（USB / UART）。
4. 加载板厂或 OpenSTLinux 提供的 **FlashLayout**（`.tsv`）及对应 **分区文件**（`fsbl`、`ssbl`、`u-boot`、`boot`、`rootfs` 等）。
5. 点击 **Download** 烧写；完成后断开 BOOT、复位，从 **SD 或 eMMC** 启动。

具体分区名、文件路径 **必须** 与所下载 OpenSTLinux 版本一致，不要混用不同版本的 tsv 与 img。

### 1.3 用 SD 卡整盘镜像（部分开发板）

1. 解压得到 `.img` / `.wic`。
2. 在 Linux/macOS：`sudo dd if=xxx.img of=/dev/sdX bs=4M status=progress conv=fsync`（`sdX` 为读卡器设备，勿写错盘）。
3. 或在 Windows 用 **Rufus / 板厂写卡工具** 写 SD。
4. 插卡上电，串口或 HDMI 看启动日志。

### 1.4 首次上电检查

- 串口终端：115200 8N1，看到 login 或 shell。
- 网络：`ping 8.8.8.8` 或 `ip addr`（天气功能需要联网）。
- 显示：若有桌面或测试图案，说明显示链路基本正常。

记下板子 IP（`ssh root@<ip>`，密码以镜像说明为准）。

## 第二步：在 PC 上准备交叉编译环境

### 2.0 WSL2 一键（推荐本机）

WSL2 + Docker（不依赖本机 sudo / ST 登录）：

```bash
# WSL 内
~/... 或仓库内：
./scripts/docker-build-mp157.sh all
# 日志: ~/mp157-dev/docker-setup.log
# 产物: ~/mp157-dev/qt-arm  ~/mp157-dev/dist/mp157-ivi.tar.gz  ~/mp157-dev/env-mp157.sh
```

说明：用 Bootlin armv7 工具链 + 自编 Qt 6.8.3（非官方 OpenSTLinux ABI）。板端优先 `QT_QPA_PLATFORM=linuxfb`。  
官方 ST SDK 可选：把 `SDK-x86_64-stm32mp1-*.tar.gz` 放到 `~/mp157-dev/downloads/` 后再跑（需从 [st.com STM32MP1Dev](https://www.st.com/en/embedded-software/stm32mp1dev.html) 自行下载）。

### 2.1 安装 / 解压官方 SDK（可选）

```bash
source /path/to/SDK/environment-setup-cortexa7t2hf-neon-vfpv4-ostl-linux-gnueabi
```

执行后 `echo $CC` 应出现 `arm-*-gcc`。

### 2.2 Qt 6.8 与目标一致

`ivi-shell` 依赖 **Qt 6.8**。交叉编译时 `IVI_QT6_DIR` 指向 ARM 版 Qt6。

### 2.3 编译天气 Shader（qsb）

在 **部署到板子前**，用与目标 GL/GLES 兼容的方式生成 `weather.frag.qsb`（与 Windows 上相同参数，qsb 用 ARM 主机或 PC 上 Qt 自带的 `qsb` 均可，需 Qt 6.8 工具链）：

```bash
cd /path/to/MP157-IVI
qsb --glsl 100es,120,330,430,440 --hlsl 50 --msl 12 \
  -o src/shell/weather.frag.qsb \
  src/shell/shaders/weather.frag
```

修改 `weather.frag` 后必须重新执行并重新编译 `ivi-shell`。

## 第三步：交叉编译 ivi-shell

在 Linux PC 上（已 source OpenSTLinux/Yocto SDK）：

```bash
cd /path/to/MP157-IVI
export IVI_SDK_ENV=/opt/st/stm32mp1/4.x/environment-setup-cortexa7t2hf-neon-ostl-linux-gnueabi
export IVI_QT6_DIR=/path/to/qt6-arm
./scripts/build-mp157.sh
./scripts/pack-mp157.sh
```

产物：`dist/mp157-ivi.tar.gz`（含 `ivi-shell`、`board-probe`、`apps/`、`feed/`、`wallpapers/`、`media/`、`run-ivi-shell.sh`；若设置了 `IVI_QT6_DIR` 还会打进 `qt/`）。

等价 CMake 预设：`cmake --preset mp157` → `cmake --build --preset mp157`（需已 source SDK，且 `IVI_QT6_DIR` 已导出）。

说明：

- Toolchain：`cmake/stm32mp157-toolchain.cmake`（读 `$CC`/`$CXX`/`$OECORE_TARGET_SYSROOT`/`$IVI_QT6_DIR`）。
- `board-probe`：板端测 `/dev/fb0`（量产测试工具同思路）。
- Linux 上 Wi‑Fi 名走 `iwgetid`/`/proc/net/wireless`；亮度写 `/sys/class/backlight/*/brightness`。

## 第四步：打包运行目录并拷到板子

### 4.1 目录布局（与 PC 调试一致）

`AppCatalog`、`WallpaperStore`、`VideoScreen` 等从 **可执行文件所在目录** 查找资源。`pack-mp157.sh` 已按此布局打包：

```text
/opt/ivi/
  ivi-shell
  board-probe
  run-ivi-shell.sh
  mp157-board-check.sh
  ivi-shell.service
  apps/
  feed/
  wallpapers/builtin/
  media/
  qt/                     # 可选，来自 IVI_QT6_DIR
```

### 4.2 Qt 运行时依赖

除 `ivi-shell` 外，板子上还需要（具体列表以 `ldd ivi-shell` 为准）：

- `libQt6Core`、`Gui`、`Qml`、`Quick`、`QuickControls2`、`Network`、`OpenGL` 等  
- 平台插件：如 `plugins/platforms/libqeglfs.so`（全屏 RGB 常用）或 `libqlinuxfb.so`  
- QML 模块：`qml/QtQuick`、`QtQml` 等  

可从 Qt ARM 安装目录拷贝，或用 Yocto 打包进 rootfs。缺插件时常见现象：进程启动即退出、QML 「module not installed」。

### 4.3 传输到板子

```bash
scp dist/mp157-ivi.tar.gz root@192.168.1.10:/tmp/
ssh root@192.168.1.10 'mkdir -p /opt/ivi && tar xzf /tmp/mp157-ivi.tar.gz -C /opt/ivi'
```

板子需有足够空间；媒体文件较大时注意 SD 容量。

---

## 第五步：在板子上运行

### 5.1 手动前台运行

```bash
cd /opt/ivi
./mp157-board-check.sh
./board-probe --no-draw          # 可选：./board-probe 会刷测试色条
./run-ivi-shell.sh               # 自动选 eglfs/linuxfb，并设置 qt/ 路径
```

若 eglfs 黑屏：

```bash
QT_QPA_PLATFORM=linuxfb ./run-ivi-shell.sh
```

`Main.qml` 在 Linux 下会 **全屏**。分辨率设计为 **1024×600**。

### 5.2 开机自启（systemd）

```bash
cp /opt/ivi/ivi-shell.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now ivi-shell
journalctl -u ivi-shell -f
```

### 5.3 网络与天气

实况天气走 HTTPS（Open-Meteo、IP 定位等）。板子需：

- 以太网或 Wi‑Fi 已配置 DNS  
- 系统时间正确（NTP），否则 TLS 可能失败  

---

## 第六步：更新应用（不重新烧整盘）

日常只改 IVI 时 **不必** 重烧 OpenSTLinux：

1. PC 上改代码 → 重新 `qsb`（若改了 shader）→ 交叉编译 `ivi-shell`。  
2. 仅替换板子上的 `ivi-shell` 与变更的 `apps/`、`media/` 等。  
3. `systemctl restart ivi-shell`。

仅当更换内核、驱动或 rootfs 版本时才需要 **第一步** 完整烧写。

## 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| CubeProgrammer 连不上 | BOOT 未进烧录模式、驱动未装 | 按原理图进 USB/UART 下载模式，重装 ST 驱动 |
| 烧写后无串口 | 错波特率、错 UART 口 | 115200，核对 CN 口说明 |
| 启动卡 U-Boot 不进内核 | 分区与 tsv 不匹配 | 整套镜像与 tsv 同源同版本 |
| `ivi-shell: not found` | 未 chmod +x 或路径错 | `chmod +x`，检查 systemd 的 WorkingDirectory |
| QML 报 module QtQuick 不存在 | 未部署 Qt QML 插件 | 拷贝 `qml/` 与 `plugins/`，设 `QML2_IMPORT_PATH` |
| 黑屏有进程 | eglfs 与显示驱动不匹配 | 换 linuxfb/kms，查 `dmesg` DRM |
| 界面卡死 | GPU/Shader 负载、网络阻塞 | 参考 PC 版优化；保证网络超时合理 |
| 天气无数据 | 无网、DNS、时间错 | `ping`、`curl https://api.open-meteo.com` |

## 与本仓库 Windows 开发的关系

| 环境 | 命令 | 用途 |
| --- | --- | --- |
| Windows | `cmake --preset windows` → `build/Debug/ivi-shell.exe` | UI 开发、天气调试 |
| ARM Linux | 本文第三～五步 | 真机 7 寸屏演示 |

两者 **共用同一套源码**；ARM 需单独 Qt6 与交叉构建目录，**不能** 把 `ivi-shell.exe` 拷到板子运行。
